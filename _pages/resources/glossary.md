This page is an effort to compile, in one location, a common set of terminology with respect to calendaring and scheduling applications and standards. The document incorporates terminology already existing in calendaring standards such as [RFC5545](https://tools.ietf.org/html/rfc5545) (Internet Calendaring and Scheduling Core Object Specification (iCalendar)), [RFC5546](https://tools.ietf.org/html/rfc6646) (iCalendar Transport-Independent Interoperability Protocol (iTIP)), [RFC6047](https://tools.ietf.org/html/rfc6047) (iCalendar Message-Based Interoperability Protocol (iMIP)), [RFC4791](https://tools.ietf.org/html/rfc4791) (Calendaring Extensions to WebDAV (CalDAV)), [RFC6638](https://tools.ietf.org/html/rfc6638) (Scheduling Extensions to CalDAV (CalDAV)), as well as input from members of the Calendaring and Scheduling Consortium (CalConnect).

Some glossary terms may not appear in published standards today. These are common calendaring terms that are included so that everyone refers to components in the same manner.

As new standards evolve, the glossary will serve as a resource for those creating documents so that all the standards share a common set of terms.

Calendaring and scheduling implementers will be able to utilize the glossary to assist them as they read and decipher calendaring standards. Calendaring and scheduling users will be able to use the glossary to help them better understand the terminology deployed by applications written using calendaring standards.

<h2 id="letter-a" class="glossary-letter">A</h2>
<details class="glossary-entry" id="Access-control">
  <summary class="glossary-term">Access Control</summary>
  <div class="glossary-def">Access control is a system which enables an authority (e.g., user or resource administrator) to control access to different entities in a calendar system. Typically vendors create Preference/Settings options to instantiate access control. Terminology varies considerably across products but broadly speaking access control is usually broken into two areas, read access and write access. Vendor terminology used for read access includes: 'read', 'reviewer', 'proxy read', 'viewer', 'see all', and 'see only freebusy'. Vendor terminology for write access includes: 'write', 'editor', 'proxy write', 'proxy', 'manager', 'administrator', 'designate', 'read/create/edit', 'make changes', 'manage', and 'edit'. (Cp. <a href="#delegate">Delegate</a> and <a href="#designate">Designate</a> below.)</div>
</details>
<details class="glossary-entry" id="access-control-list">
  <summary class="glossary-term">Access Control List (ACL)</summary>
  <div class="glossary-def">A list of access control elements that define access control to a particular calendar system entity. (Reference: <a href="https://tools.ietf.org/html/rfc3744">RFC3744</a> for its use in a WebDAV context.)</div>
</details>
<details class="glossary-entry" id="accessibility">
  <summary class="glossary-term">Accessibility</summary>
  <div class="glossary-def">Information pertaining to access to a resource by the physically disabled. This applies to Location Resources.</div>
</details>
<details class="glossary-entry" id="admittance-info">
  <summary class="glossary-term">Admittance Info</summary>
  <div class="glossary-def">All information required to gain access to a resource. It applies to Location Resources.</div>
</details>
<details class="glossary-entry" id="agenda">
  <summary class="glossary-term">Agenda</summary>
  <div class="glossary-def">See <a href="#calendar">Calendar</a>.</div>
</details>
<details class="glossary-entry" id="alarm">
  <summary class="glossary-term">Alarm</summary>
  <div class="glossary-def">Use of the terms alarm, reminder, alert, and notifications vary by implementation and can represent several things. They can represent a setting applied to an event by which a user indicates they want a 'notification' to be triggered to 'remind' them about some event or action (cp. <a href="#valarm">VALARM</a> in <a href="https://tools.ietf.org/html/rfc5545">RFC5545</a>. They can also be used to designate the type of 'alert' that serves as the notification (e.g., email message, audible sound, pop-up window). (Reference <a href="https://tools.ietf.org/html/rfc4791">RFC4791 (CalDAV)</a>, <a href="https://tools.ietf.org/html/rfc5545#section-3.6.6">RFC5545</a>, <a href="https://tools.ietf.org/html/rfc5546">RFC5546 (iTip)</a>.)</div>
</details>
<details class="glossary-entry" id="application-calendar-xml">
  <summary class="glossary-term">Application/calendar + XML</summary>
  <div class="glossary-def">The MIME content type that indicates an iCalendar object expressed in XML.</div>
</details>
<details class="glossary-entry" id="appointment">
  <summary class="glossary-term">Appointment</summary>
  <div class="glossary-def">See <a href="#calendar">Calendar</a>.</div>
</details>
<details class="glossary-entry" id="attachment">
  <summary class="glossary-term">Attachment</summary>
  <div class="glossary-def">A document object associated with a calendar component.</div>
</details>
<details class="glossary-entry" id="attendee">
  <summary class="glossary-term">Attendee</summary>
  <div class="glossary-def">Specifies the participants or non-participants (e.g., room or resources) for an event. This property in iCalendar can contain multiple attributes specifying additional information, i.e., role, participation status, group membership, delegation, etc. (Reference: <a href="https://tools.ietf.org/html/rfc5545#section-3.6.4.1">RFC5545</a>.)</div>
</details>
<details class="glossary-entry" id="autoconfiguration">
  <summary class="glossary-term">Autoconfiguration</summary>
  <div class="glossary-def">The process of configuring clients such as mobile devices or desktop applications to access a service, or class of service, with a minimum of input from the user of the device. See also <a href="#autodiscovery">Autodiscovery</a>.</div>
</details>
<details class="glossary-entry" id="autodiscovery">
  <summary class="glossary-term">Autodiscovery</summary>
  <div class="glossary-def">The process used to determine the services provided by a host, or for a domain, including retrieval of the recommended configuration values for those services. The autodiscovery functionality requires the service provider to declare in a standard way which services are available and what their configuration looks like for the requesting user. See also <a href="#autoconfiguration">Autoconfiguration</a>. (Reference: <a href="https://datatracker.ietf.org/doc/draft-daboo-aggregated-service-discovery/">draft-daboo-aggregated-service-discovery</a>.)</div>
</details>
<details class="glossary-entry" id="autoschedule">
  <summary class="glossary-term">Autoschedule</summary>
  <div class="glossary-def">Accept scheduling invitations automatically with no human intervention.</div>
</details>

<h2 id="letter-c" class="glossary-letter">C</h2>
<details class="glossary-entry" id="caldav">
  <summary class="glossary-term">CalDAV</summary>
  <div class="glossary-def">Extensions to the Web Distributed Authoring and Versioning (WebDAV) protocol to specify a standard way of accessing, managing and sharing calendar data based on the iCalendar format. Defined by two specifications, the first, <a href="https://tools.ietf.org/html/rfc4791">RFC4791 (CalDAV)</a>, specifies a calendar access protocol that allows Calendar User Agents to access and manage calendar data. The second specification, RFC 6638, specifies a standard way of performing scheduling transactions with iCalendar-based calendar components. This document defines the "calendar-auto-schedule" feature of CalDAV. (Reference: <a href="https://tools.ietf.org/html/rfc4791">RFC 4791</a>, and <a href="https://tools.ietf.org/html/rfc6638">RFC 6638</a>.)</div>
</details>
<details class="glossary-entry" id="calendar">
  <summary class="glossary-term">Calendar</summary>
  <div class="glossary-def">A collection of calendar items such as events, tasks, journal entries, etc. Examples include a person's or group's schedule, resource availability, and event listings. Typically an individual may own multiple calendars based on the same or different services.</div>
</details>
<details class="glossary-entry" id="calendar-access-rights">
  <summary class="glossary-term">Calendar Access Rights</summary>
  <div class="glossary-def">See <a href="#access-control">Access Control</a>, <a href="#access-control-list">Access Control List</a>, <a href="#delegate">Delegate</a>, and <a href="#designate">Designate</a>.</div>
</details>
<details class="glossary-entry" id="calendar-collection">
  <summary class="glossary-term">Calendar Collection</summary>
  <div class="glossary-def">A WebDAV collection used to represent a calendar containing a set of calendar object resources. (Reference: <a href="https://tools.ietf.org/html/rfc4791">RFC4791</a> and <a href="https://tools.ietf.org/html/rfc5545#section-3.4">RFC5545</a>.)</div>
</details>
<details class="glossary-entry" id="calendar-object-resource">
  <summary class="glossary-term">Calendar Object Resource</summary>
  <div class="glossary-def">A WebDAV resource representing an iCalendar component typically stored inside a Calendar Collection (cp. Component). (Reference: <a href="https://tools.ietf.org/html/rfc4791">RFC4791</a>.)</div>
</details>
<details class="glossary-entry" id="calendar-service">
  <summary class="glossary-term">Calendar Service</summary>
  <div class="glossary-def">A server application that provides calendar user agents access to calendar stores.</div>
</details>
<details class="glossary-entry" id="calendar-store">
  <summary class="glossary-term">Calendar Store (CS)</summary>
  <div class="glossary-def">A data repository that may contain several calendars as well as properties and components of those calendars. A local calendar store is on the same device as the calendar user agent (<a href="#calendar-user-agent">CUA</a>). A remote calendar store is not on the same machine/device as the calendar user agent. (Reference: <a href="https://tools.ietf.org/html/rfc3283">RFC3283</a>.)</div>
</details>
<details class="glossary-entry" id="calendar-subscription">
  <summary class="glossary-term">Calendar Subscription</summary>
  <div class="glossary-def">See <a href="#subscribed-calendar">Subscribed Calendar</a></div>
</details>
<details class="glossary-entry" id="calendar-user">
  <summary class="glossary-term">Calendar User (CU)</summary>
  <div class="glossary-def">A person who accesses or modifies calendar information.</div>
</details>
<details class="glossary-entry" id="calendar-user-agent">
  <summary class="glossary-term">Calendar User Agent (CUA)</summary>
  <div class="glossary-def">1. Software with which the calendar user communicates with a calendar service or local calendar store to access calendar information. 2. Software that gathers calendar data on the Calendar User's behalf.</div>
</details>
<details class="glossary-entry" id="calendar-system">
  <summary class="glossary-term">Calendar System</summary>
  <div class="glossary-def">A way to represent dates as a combination of eras, years, months, weeks, and days in formats used in many different parts of the world. A calendar system also defines the limits for those different quantities and how "date arithmetic" can be done to implement repeating dates. (See <a href="http://en.wikipedia.org/wiki/Calendar">Wikipedia:Calendar</a> for a description of many different calendar systems.)</div>
</details>
<details class="glossary-entry" id="calconnect">
  <summary class="glossary-term">CalConnect</summary>
  <div class="glossary-def">The Calendaring and Scheduling Consortium is a non-for-profit partnership between vendors of calendaring and scheduling systems and tools, and users of those tools. Our purpose is to improve all aspects of calendaring and scheduling, in particular interoperability. We do this by improving existing standards, developing new standards, offering interoperability testing for calendaring and scheduling systems and tools, collaborating with other organizations with similar goals, and conducting periodic conferences where engineers and customers meet and interact in a collegial atmosphere. Virtually every important calendaring or calendaring-related standard since the late 2000s has been authored, edited and/or coedited by members of a CalConnect Technical Committee.</div>
</details>
<details class="glossary-entry" id="calext">
  <summary class="glossary-term">CALEXT</summary>
  <div class="glossary-def">The IETF mailing list most commonly used for calendaring and scheduling standards development. See the page at <a href="https://www.ietf.org/mailman/listinfo/calsify">https://www.ietf.org/mailman/listinfo/calsify</a> to join.</div>
</details>
<details class="glossary-entry" id="calscale">
  <summary class="glossary-term">Calscale</summary>
  <div class="glossary-def">An iCalendar property used to identify the calendar system used to represent dates and times within an iCalendar object. iCalendar currently only defines the GREGORIAN calendar system.</div>
</details>
<details class="glossary-entry" id="calws">
  <summary class="glossary-term">CalWS</summary>
  <div class="glossary-def">CalWS-REST is a CalConnect Proposal and CalWS-SOAP will be a parallel CalConnect Proposal which define an API of basic operations which allow creation, retrieval, update and deletion of calendar objects. In addition, query and freebusy operations are defined to allow efficient, partial retrieval of calendar data. (Reference: CalWS-REST Restful Web Services Protocol for Calendaring.)</div>
</details>
<details class="glossary-entry" id="capacity">
  <summary class="glossary-term">Capacity</summary>
  <div class="glossary-def">Capacity of a resource, expressed as a numerical quantity. This applies to a Location Resource.</div>
</details>
<details class="glossary-entry" id="carddav">
  <summary class="glossary-term">CardDAV</summary>
  <div class="glossary-def">Extensions to the Web Distributed Authoring and Versioning (WebDAV) protocol to specify a standard way of accessing, managing, and sharing contact information based on the vCard format. (Reference: <a href="https://tools.ietf.org/html/rfc6352">RFC6352</a></div>
</details>
<details class="glossary-entry" id="consensus-scheduling">
  <summary class="glossary-term">Consensus Scheduling</summary>
  <div class="glossary-def">The process whereby a group comes to agreement on when and perhaps where to hold a meeting or carry out a task, by identifying the "best" time or location to help maximize participation and minimize inconvenience. For more information see 7 Things You Should Know About Consensus Scheduling. (See <a href="#vpoll">VPOLL</a>.)</div>
</details>
<details class="glossary-entry" id="counter">
  <summary class="glossary-term">Counter</summary>
  <div class="glossary-def">A response sent by an Attendee of an event to the event Organizer to propose a change to the event or task such as the scheduled date/time, list of participants, etc. (Reference: <a href="https://tools.ietf.org/html/rfc5546">RFC5546</a>)</div>
</details>

<h2 id="letter-d" class="glossary-letter">D</h2>
<details class="glossary-entry" id="delegate">
  <summary class="glossary-term">Delegate</summary>
  <div class="glossary-def">In common usage 'delegate' may mean either a person who acts for someone else (cp. <a href="#designate">Designate</a>) or refer to the act of appointing someone as a representative. The term has very specific meaning in the iCalendar and iTIP RFCs. In iCalendar, delegate means to specify that another individual, rather than oneself, should attend an event (cp. <a href="#delegator">Delegator</a> and <a href="#delegatee">Delegatee</a>). In iTIP, delegate means to assign ownership of a task to another individual. (Reference: <a href="https://tools.ietf.org/html/rfc5545#section-3.2.4">RFC5545</a> and <a href="https://tools.ietf.org/html/rfc5546">RFC5546</a>)</div>
</details>
<details class="glossary-entry" id="delegatee">
  <summary class="glossary-term">Delegatee</summary>
  <div class="glossary-def">The attribute in iCalendar that specifies the calendar user(s) to whom a calendar user has delegated participation in an event. The actual attribute name is DELEGATED-TO. (Reference: <a href="https://tools.ietf.org/html/rfc5545#section-3.2.5">RFC5545</a>.)</div>
</details>
<details class="glossary-entry" id="delegator">
  <summary class="glossary-term">Delegator</summary>
  <div class="glossary-def">The attribute in iCalendar that specifies the calendar user(s) that have delegated their participation in an event to another calendar user. The actual attribute name is DELEGATED-FROM. (Reference: <a href="https://tools.ietf.org/html/rfc5545#section-3.2.4">RFC5545</a>.)</div>
</details>
<details class="glossary-entry" id="designate">
  <summary class="glossary-term">Designate</summary>
  <div class="glossary-def">The DTEND property for a VEVENT calendar component specifies the non-inclusive end of the event. (Reference: <a href="https://tools.ietf.org/html/rfc5545#section-3.6.2.2">RFC5545</a>.)</div>
</details>
<details class="glossary-entry" id="dtend">
  <summary class="glossary-term">DTEND</summary>
  <div class="glossary-def">The DTEND property for a VEVENT calendar component specifies the non-inclusive end of the event. (Reference: <a href="https://tools.ietf.org/html/rfc5545#section-3.6.2.2">RFC5545</a>.)</div>
</details>
<details class="glossary-entry" id="dtstart">
  <summary class="glossary-term">DTSTART</summary>
  <div class="glossary-def">The DTSTART property for a VEVENT specifies the inclusive start of the event. For recurring events, it also specifies the very first instance in the recurrence set. (Reference: <a href="https://tools.ietf.org/html/rfc5545#section-3.6.2.4">RFC5545</a>.)</div>
</details>

<h2 id="letter-e" class="glossary-letter">E</h2>
<details class="glossary-entry" id="event">
  <summary class="glossary-term">Event</summary>
  <div class="glossary-def">A calendar object that is commonly used to represent things that mark time or use time. Examples include meetings, appointments, anniversaries, start times, arrival times, closing times.</div>
</details>
<details class="glossary-entry" id="event-publication">
  <summary class="glossary-term">Event Publication</summary>
  <div class="glossary-def">The process by which public event data is gathered, formatted and distributed to calendar users. Often this takes the form of public, unauthenticated clients and/or feeds. See <a href="#public-event">Public Event</a>.</div>
</details>

<h2 id="letter-f" class="glossary-letter">F</h2>
<details class="glossary-entry" id="freebusy">
  <summary class="glossary-term">Freebusy</summary>
  <div class="glossary-def">A list of free and busy periods for a particular calendar user or resource. Primarily used for scheduling resources or meetings with other people. Time periods may be marked as busy, free, busy-unavailable (sometimes referred to as out of office) and busy-tentative.</div>
</details>

<h2 id="letter-g" class="glossary-letter">G</h2>
<details class="glossary-entry" id="gregorian-calendar">
  <summary class="glossary-term">Gregorian Calendar</summary>
  <div class="glossary-def">The most common civil calendar system in use today, recognized by <a href="http://en.wikipedia.org/wiki/Gregorian_calendar">many international bodies</a></div>
</details>

<h2 id="letter-i" class="glossary-letter">I</h2>
<details class="glossary-entry" id="ical">
  <summary class="glossary-term">iCal</summary>
  <div class="glossary-def">The name of Apple, Inc's desktop calendar user agent. Often used as an abbreviation for the iCalendar standard.</div>
</details>
<details class="glossary-entry" id="icalendar">
  <summary class="glossary-term">iCalendar</summary>
  <div class="glossary-def">The Internet Calendaring and Scheduling Core Object Specification. An IETF standard (<a href="https://tools.ietf.org/html/rfc5545">RFC5545</a>) for a text representation of calendar data. Scheduling operations are specified in <a href="https://tools.ietf.org/html/rfc5546">RFC5546</a>.</div>
</details>
<details class="glossary-entry" id="ietf">
  <summary class="glossary-term">IETF (The Internet Engineering Task Force)</summary>
  <div class="glossary-def">According to IETF <a href="https://tools.ietf.org/html/rfc3935">RFC3935</a>, "The IETF has traditionally been a community for experimentation with things that are not fully understood, standardization of protocols for which some understanding has been reached, and publication of (and refinement of) protocols originally specified outside the IETF process ...The mission of the IETF is to produce high quality, relevant technical and engineering documents that influence the way people design, use, and manage the Internet in such a way as to make the Internet work better. These documents include protocol standards, best current practices, and informational documents of various kinds."</div>
</details>
<details class="glossary-entry" id="imip">
  <summary class="glossary-term">iMIP (iCalendar Message-Based Interoperability Protocol)</summary>
  <div class="glossary-def">An IETF standard (<a href="https://tools.ietf.org/html/rfc6047">RFC6047</a>) that describes how iTIP messages are exchanged via email.</div>
</details>
<details class="glossary-entry" id="itip">
  <summary class="glossary-term">iTIP (iCalendar Transport-Independent Interoperability Protocol)</summary>
  <div class="glossary-def">An IETF Standard (<a href="https://tools.ietf.org/html/rfc5546">RFC5546</a>) that specifies a protocol that uses the iCalendar object specification to provide scheduling interoperability between different calendar systems without reference to a specific transport protocol so as to allow multiple methods of communication between systems (see <a href="#imip">iMIP</a>, <a href="#ischedule">iSchedule</a>).</div>
</details>
<details class="glossary-entry" id="ischedule">
  <summary class="glossary-term">iSchedule</summary>
  <div class="glossary-def">A draft specification that describes how iTIP messages are exchanged via HTTP (Reference: <a href="https://tools.ietf.org/html/draft-desruisseaux-ischedule-05">Internet Calendar Scheduling Protocol (iSchedule) draft-desruisseaux-ischedule</a>.)</div>
</details>
<details class="glossary-entry" id="instance">
  <summary class="glossary-term">Instance</summary>
  <div class="glossary-def">A single event of a larger group of events specified as a recurring event (cp. Recurring). (Reference: <a href="https://tools.ietf.org/html/rfc4791">RFC4791 (CalDAV)</a> and <a href="https://tools.ietf.org/html/rfc5545#section-3.8.4.4">RFC5545</a>.)</div>
</details>
<details class="glossary-entry" id="inventory-info">
  <summary class="glossary-term">Inventory Info</summary>
  <div class="glossary-def">All information on other resources available as part of a resource.</div>
</details>
<details class="glossary-entry" id="invitation-invite">
  <summary class="glossary-term">Invitation/Invite</summary>
  <div class="glossary-def">A general term from common usage to convey a request for an attendee's participation in an event. In RFC documents the more specific term is request (cp. <a href="#request">Request</a>).</div>
</details>

<h2 id="letter-j" class="glossary-letter">J</h2>
<details class="glossary-entry" id="jcal">
  <summary class="glossary-term">jCal</summary>
  <div class="glossary-def">A draft specification that defines a JSON representation of vCard data. Reference: <a href="https://datatracker.ietf.org/doc/rfc7095/">jCard - The JSON format for vCard</a></div>
</details>
<details class="glossary-entry" id="journal-entry">
  <summary class="glossary-term">Journal Entry</summary>
  <div class="glossary-def">From <a href="https://tools.ietf.org/html/rfc5545">RFC5545</a>, one or more descriptive text notes associated with a particular calendar date. Examples of a journal entry include a daily record of a legislative body or a journal entry of individual telephone contacts for the day or an ordered list of accomplishments for the day.</div>
</details>

<h2 id="letter-m" class="glossary-letter">M</h2>
<details class="glossary-entry" id="managed-attachment">
  <summary class="glossary-term">Managed Attachment</summary>
  <div class="glossary-def">An attachment associated with a calendar component that is stored and managed on a CalDAV server. (Reference <a href="https://tools.ietf.org/html/draft-daboo-caldav-attachments-03">draft-daboo-caldav-attachments</a>.)</div>
</details>
<details class="glossary-entry" id="maximum-instances">
  <summary class="glossary-term">Maximum Instances</summary>
  <div class="glossary-def">Maximum number of instances of an event a resource can be scheduled for from a given point in time.</div>
</details>
<details class="glossary-entry" id="meeting">
  <summary class="glossary-term">Meeting</summary>
  <div class="glossary-def">An acronym for Multipurpose Internet Mail Extensions, a specification for formatting non-ASCII text message content, including iCalendar data, graphics, audio and video, so that they can be sent over the Internet. MIME is supported by email clients and web browsers (see <a href="https://tools.ietf.org/html/rfc2045">RFC2045</a>, <a href="https://tools.ietf.org/html/rfc2046">RFC2046</a>, <a href="https://tools.ietf.org/html/rfc2047">RFC2047</a>).</div>
</details>
<details class="glossary-entry" id="mime-type">
  <summary class="glossary-term">Mime Type</summary>
  <div class="glossary-def">An Internet media type, sometimes a Content-type after the name of a header in several protocols whose value is such a type, is a two-part identifier for file formats on the Internet. The identifiers were originally defined in <a href="https://tools.ietf.org/html/rfc2046">RFC2046</a> for use in e-mail sent through SMTP, but their use has expanded to other protocols such as HTTP, RTP and SIP and for other uses (e.g., OS-level file type identification for application/file association).</div>
</details>
<details class="glossary-entry" id="multiple-bookings">
  <summary class="glossary-term">Multiple Bookings</summary>
  <div class="glossary-def">Number of simultaneous bookings allowed by a resource, during scheduling.</div>
</details>

<h2 id="letter-n" class="glossary-letter">N</h2>
<details class="glossary-entry" id="non-gregorian-calendar">
  <summary class="glossary-term">Non-Gregorian Calendar</summary>
  <div class="glossary-def">Any calendar system that is not a Gregorian Calendar (e.g., Chinese, Hebrew, Islamic). See <a href="http://en.wikipedia.org/wiki/Calendar">Wikipedia</a> for a description of many different calendar systems.</div>
</details>
<details class="glossary-entry" id="notification">
  <summary class="glossary-term">Notification</summary>
  <div class="glossary-def">See <a href="#alarm">Alarm</a>.</div>
</details>

<h2 id="letter-o" class="glossary-letter">O</h2>
<details class="glossary-entry" id="oasis">
  <summary class="glossary-term">OASIS (Organization for the Advancement of Structured Information Standards)</summary>
  <div class="glossary-def">A Standards Development Organization primarily focused on web services standards. <a href="http://www.oasis-open.org">OASIS</a> and CalConnect have reciprocal memberships for joint work on WS-Calendar.</div>
</details>
<details class="glossary-entry" id="organizer">
  <summary class="glossary-term">Organizer</summary>
  <div class="glossary-def">A calendar user who creates a calendar item, requests free/busy information, or published free/busy information. It is an Organizer who invites Attendees. (Reference: <a href="https://tools.ietf.org/html/rfc5545#section-3.8.4.3">RFC5545</a>.)</div>
</details>

<h2 id="letter-p" class="glossary-letter">P</h2>
<details class="glossary-entry" id="personal-calendar">
  <summary class="glossary-term">Personal Calendar</summary>
  <div class="glossary-def">A calendar containing events for one calendar user (the owner), and typically only accessible to the owner, or others authorized by the owner (cp. Calendar, Public Calendar, Shared Calendar).</div>
</details>
<details class="glossary-entry" id="priority">
  <summary class="glossary-term">Priority</summary>
  <div class="glossary-def">A level of importance and/or urgency calendar users can apply to Tasks and Events. (Reference: <a href="https://tools.ietf.org/html/rfc5545#section-3.8.1.9">RFC5545</a>.)</div>
</details>
<details class="glossary-entry" id="property">
  <summary class="glossary-term">Property</summary>
  <div class="glossary-def">RFCs define the objects and components of their subject which in turn have properties which have values (sometimes referred to as 'property parameters' or 'property attributes'). These "property parameters" contain meta-information about the property or the property value. Property parameters are provided to specify such information as the location of an alternate text representation for a property value, the language of a text property value, the value type of the property value, and other attributes. Throughout this glossary are references to component, property, and attribute following this usage. (Reference: <a href="https://tools.ietf.org/html/rfc5545#section-3.8">RFC5545</a>.)</div>
</details>
<details class="glossary-entry" id="public-calendar">
  <summary class="glossary-term">Public Calendar</summary>
  <div class="glossary-def">A calendar containing primarily public events and accessible to anyone or a specific group of calendar users (cp. Calendar, Personal Calendar, Shared Calendar). See <a href="#public-event">Public Event</a>.</div>
</details>
<details class="glossary-entry" id="public-event">
  <summary class="glossary-term">Public Event</summary>
  <div class="glossary-def">An event meant to be published to or distributed to anyone or a specific group of calendar users. These generally differ from personal events in that they contain much more detail about the event, its location, categories and other properties. See Event Publication and Publish.</div>
</details>
<details class="glossary-entry" id="publish">
  <summary class="glossary-term">Publish</summary>
  <div class="glossary-def">Generally, to make calendar information, such as freebusy time, available to a select group or to the public. From the RFC for iTIP, "The 'PUBLISH' method in a 'VEVENT' calendar component is an unsolicited posting of an iCalendar object."</div>
</details>

<h2 id="letter-r" class="glossary-letter">R</h2>
<details class="glossary-entry" id="rrule">
  <summary class="glossary-term">RRULE</summary>
  <div class="glossary-def">An iCalendar property used to define a repeating pattern for events or tasks.</div>
</details>
<details class="glossary-entry" id="rscale">
  <summary class="glossary-term">RSCALE</summary>
  <div class="glossary-def">An iCalendar RRULE parameter indicating which calendar system to use for expanding this <a href="http://tools.ietf.org/html/rfc7529">RRULE</a>.</div>
</details>
<details class="glossary-entry" id="recurrence-id">
  <summary class="glossary-term">RECURRENCE-ID</summary>
  <div class="glossary-def">This property is used to identify a specific instance of a recurring VEVENT, VTODO, or VJOURNAL calendar component.</div>
</details>
<details class="glossary-entry" id="recurring">
  <summary class="glossary-term">Recurring</summary>
  <div class="glossary-def">An event or task that happens more than once either with a regular interval (ex. daily, weekly, monthly) that can be expressed by a rule or with an explicit series of dates/times.</div>
</details>
<details class="glossary-entry" id="request">
  <summary class="glossary-term">Request</summary>
  <div class="glossary-def">A broadly used term in multiple RFCs to represent an action. That action may be a query for property values from a client to a server (cp. <a href="https://tools.ietf.org/html/rfc4791">RFC4791</a>, a query between a client and a server that results in object creation, modification, or deletion (cp. <a href="https://tools.ietf.org/html/rfc4791">RFC4791</a> and <a href="https://tools.ietf.org/html/rfc5545">RFC5545</a>), and it is the name of a method in iTIP that makes "an explicit invitation to one or more attendees" (among other things, cp. RFC5546). (Reference: <a href="https://tools.ietf.org/html/rfc4791">RFC4791</a>, <a href="https://tools.ietf.org/html/rfc5545#section-3.7.2">RFC5545</a>, <a href="https://tools.ietf.org/html/rfc5546">RFC5546</a>, and Internet Calendar Scheduling Protocol (<a href="#ischedule">iSchedule</a>).)</div>
</details>
<details class="glossary-entry" id="reminder">
  <summary class="glossary-term">Reminder</summary>
  <div class="glossary-def">See <a href="#alarm">Alarm</a>.</div>
</details>
<details class="glossary-entry" id="repeating">
  <summary class="glossary-term">Repeating</summary>
  <div class="glossary-def">See <a href="#recurring">Recurring</a>.</div>
</details>
<details class="glossary-entry" id="resource">
  <summary class="glossary-term">Resource</summary>
  <div class="glossary-def">A resource in the scheduling context is any shared entity, that can be scheduled by a calendar user, but does not control its own attendance status. Resources can be of "Location", "Equipment", or "Role" type.</div>
</details>
<details class="glossary-entry" id="rvsp">
  <summary class="glossary-term">RSVP</summary>
  <div class="glossary-def">Specifies whether there is an expectation of a reply from a specific calendar user (Reference: <a href="https://tools.ietf.org/html/rfc5545#section-3.2.17">RFC5545</a>.)</div>
</details>

<h2 id="letter-s" class="glossary-letter">S</h2>
<details class="glossary-entry" id="scheduling">
  <summary class="glossary-term">Scheduling</summary>
  <div class="glossary-def">Briefly, the process by which organizers and attendees plan events or assign tasks. More specifically the term encompasses the exchange of request/invitations and responses between organizers and attendees of scheduled events, tasks or journal entries.</div>
</details>
<details class="glossary-entry" id="scheduling-admin-contact-info">
  <summary class="glossary-term">Scheduling Admin Contact Info</summary>
  <div class="glossary-def">An attribute that contains contact information for the scheduling approvers, if approval is required.</div>
</details>
<details class="glossary-entry" id="shared-calendar">
  <summary class="glossary-term">Shared Calendar</summary>
  <div class="glossary-def">A calendar that is accessible to multiple calendar users. Typically there is an "owner" and a set of "sharees", some of whom may have read-only access and some of whom might have read/write access (cp. <a href="#calendar">Calendar</a>, <a href="#personal-calendar">Personal Calendar</a>, <a href="#public-calendar">Public Calendar</a>, <a href="#subscribed-calendar">Subscribed Calendar</a>).</div>
</details>
<details class="glossary-entry" id="subscribed-calendar">
  <summary class="glossary-term">Subscribed Calendar</summary>
  <div class="glossary-def">A calendar that has been published, typically on an HTTP server. See <a href="#publish">Publish</a>.</div>
</details>

<h2 id="letter-t" class="glossary-letter">T</h2>
<details class="glossary-entry" id="task">
  <summary class="glossary-term">Task</summary>
  <div class="glossary-def">A representation of an item of work assigned to an individual. In <a href="https://tools.ietf.org/html/rfc5545">RFC5545</a>, these are "VTODO" calendar components, which are groupings of component properties and possibly "VALARM" calendar components that represent an action-item or assignment.</div>
</details>
<details class="glossary-entry" id="text-calendar">
  <summary class="glossary-term">Text/calendar</summary>
  <div class="glossary-def">The MIME content type for encoding iCalendar objects. Example usage includes: email, web pages.</div>
</details>
<details class="glossary-entry" id="timezone">
  <summary class="glossary-term">Timezone also Time Zone</summary>
  <div class="glossary-def">Areas of the Earth that have adopted the same local time. Time zones are generally centered on meridians of a longitude, that is a multiple of 15, thus making neighbouring time zones one hour apart. However, the one hour separation is not universal and the shapes of time zones can be quite irregular because they usually follow the boundaries of states, countries or other administrative areas. In <a href="https://tools.ietf.org/html/rfc5545">RFC5545</a>, time zones are represented using "VTIMEZONE" calendar components, each with a Time Zone Identifier (TZID) that can be used to tie a particular date and time to a specific timezone.</div>
</details>
<details class="glossary-entry" id="timezone-service">
  <summary class="glossary-term">Timezone Service</summary>
  <div class="glossary-def">A client/server protocol used for distributing Timezone data. The protocol improves the accuracy and speed of distributing timezone data to ensure clients are kept up to date with sometimes rapidly changing definitions. It also allows clients to avoid having a complete database of all timezones - instead they can download timezone data on a case-by-case basis. (Reference <a href="https://datatracker.ietf.org/doc/html/draft-douglass-timezone-service">draft-douglass-timezone-service</a>.)</div>
</details>
<details class="glossary-entry" id="transparency">
  <summary class="glossary-term">Transparency</summary>
  <div class="glossary-def">A property of an event that defines whether it will appear free or busy in free/busy time searches.</div>
</details>

<h2 id="letter-v" class="glossary-letter">V</h2>
<details class="glossary-entry" id="valarm">
  <summary class="glossary-term">VALARM</summary>
  <div class="glossary-def">A VALARM calendar component is a grouping of component properties that is a reminder or alarm for an event or a to-do. For example, it may be used to define a reminder for a pending event or an overdue to-do. VALARMs will thus be included within VEVENT and VTODO components. VAVAILABILITY - An iCalendar component that is used to describe periods of time for which a calendar user is available for scheduling of events. (Reference: <a href="https://tools.ietf.org/html/draft-daboo-calendar-availability.">draft-daboo-calendar-availability</a></div>
</details>
<details class="glossary-entry" id="vcalendar">
  <summary class="glossary-term">vCalendar</summary>
  <div class="glossary-def">A text representation of calendar and scheduling data created by the Versit consortium (also, the vCalendar specification). The <a href="https://tools.ietf.org/html/rfc5545">RFC5545</a> iCalendar specification supersedes the work of vCalendar, though VCALENDAR remains as a component type in the <a href="https://tools.ietf.org/html/rfc5545">RFC5545</a> iCalendar specification.</div>
</details>
<details class="glossary-entry" id="vCard">
  <summary class="glossary-term">vCard</summary>
  <div class="glossary-def">An IETF standard for a text representation of contact data. See CardDAV. (Reference: <a href="https://tools.ietf.org/html/rfc2426">RFC2426</a> vCard V3.0, <a href="https://tools.ietf.org/html/rfc6350">RFC6350</a> vCard V4.0.)</div>
</details>
<details class="glossary-entry" id="vevent">
  <summary class="glossary-term">VEVENT</summary>
  <div class="glossary-def">A VEVENT calendar component represents a scheduled amount of time on a calendar. For example, it can be an activity; such as a one-hour long, department meeting from 8:00 AM to 9:00 AM, tomorrow. Generally, an event will take up time on an individual calendar. The VEVENT is also the calendar component used to specify an anniversary or daily reminder within a calendar.</div>
</details>
<details class="glossary-entry" id="vfreebusy">
  <summary class="glossary-term">VFREEBUSY</summary>
  <div class="glossary-def">A grouping of component properties that represents either a request for free or busy time information, a reply to a request for free or busy time information, or a published set of busy time information.</div>
</details>
<details class="glossary-entry" id="vjournal">
  <summary class="glossary-term">VJOURNAL</summary>
  <div class="glossary-def">A VJOURNAL calendar component is a grouping of component properties that represent one or more descriptive text notes associated with a particular calendar date. The DTSTART property is used to specify the calendar date with which the journal entry is associated. Examples of a journal entry include a daily record of a legislative body or a journal entry of individual telephone contacts for the day or an ordered list of accomplishments for the day. The VJOURNAL calendar component can also be used to associate a document with a calendar date.</div>
</details>
<details class="glossary-entry" id="voll">
  <summary class="glossary-term">VPOLL</summary>
  <div class="glossary-def">A proposed extension to iCalendar. VPOLL is a new component which allows conducting a "poll" via iTIP exchanges to accomplish consensus scheduling for an event or appointment. See Consensus Scheduling. (Reference: <a href="https://datatracker.ietf.org/doc/draft-york-vpoll/">draft-york-vpoll</a>.)</div>
</details>
<details class="glossary-entry" id="vtodo">
  <summary class="glossary-term">VTODO</summary>
  <div class="glossary-def">A VTODO calendar component is a grouping of component properties and possibly VALARM calendar components that represent an action-item or assignment. For example, it can be used to represent an item of work assigned to an individual; such as "turn in travel expense today".</div>
</details>

<h2 id="letter-w" class="glossary-letter">W</h2>
<details class="glossary-entry" id="webdav">
  <summary class="glossary-term">WebDAV</summary>
  <div class="glossary-def">Web Distributed Authoring and Versioning (WebDAV) is an extension of the Hypertext Transfer Protocol (HTTP) that facilitates collaboration between users in editing and managing documents and files stored on World Wide Web servers. See <a href="#caldav">CalDAV</a> and <a href="#carddav">CardDAV</a>. (Reference: <a href="https://tools.ietf.org/html/rfc4918">RF4918</a>.)</div>
</details>
<details class="glossary-entry" id="webdav-sync">
  <summary class="glossary-term">WebDAV Sync</summary>
  <div class="glossary-def">An extension to Web Distributed Authoring and Versioning (WebDAV) that allows efficient synchronization of the contents of a WebDAV collection. (Reference: <a href="https://tools.ietf.org/html/rfc6578">RFC6578</a>.)</div>
</details>
<details class="glossary-entry" id="ws-calendar">
  <summary class="glossary-term">WS-Calendar</summary>
  <div class="glossary-def">An OASIS (Organization for the Advancement of Structured Information Standards) working group tasked with defining a cross-domain standard for passing schedule and interval information between and within services built around CalWS. The product of the working group will be a standard also named <a href="http://www.oasis-open.org/committees/workgroup.php?wg_abbrev=ws-calendar">WS-Calendar</a> incorporating the CalWS proposal. See <a href="#calws">CalWS</a>.</div>
</details>

        h.style.display = hasVisible || !q ? '' : 'none';
      });
    });
  }

  // Auto-open if hash matches
  function openHashTarget() {
    var hash = window.location.hash.slice(1);
    if (hash) {
      var target = document.getElementById(hash);
      if (target && target.classList.contains('glossary-entry')) {
        target.open = true;
        target.scrollIntoView({ behavior: 'smooth', block: 'center' });
      }
    }
  }
  openHashTarget();
  window.addEventListener('hashchange', openHashTarget);
})();
